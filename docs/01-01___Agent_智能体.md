# Agent（智能体）

**一句话总述：**Agent是一套以AI模型（通常LLM）为大脑，具备推理规划、调用工具、与环境交互来达成用户目标的系统。

## 一、先看一个故事：管家 Alfred

想象你有一个管家叫 Alfred。你对他说："Alfred，请给我来一杯咖啡。"他会怎么做？

1. **理解你的话：**Alfred 听懂自然语言，明白你要的是咖啡
2. **推理与规划：**他在脑中列出步骤：走到厨房 → 使用咖啡机 → 冲泡 → 端回来
3. **调用工具执行：**他操作咖啡机（工具），把咖啡冲泡好
4. **交付结果：**他把咖啡端到你面前

这个流程就是 Agent 的工作方式。所以 Agent 可以理解为：**能够推理、规划，并与环境互动的 AI**。它之所以叫 Agent，是因为它有"自主性（Agency）"——即主动与环境交互、完成任务的能力。

## 二、Agent 的两大组成：大脑 + 身体

把 Agent 拆开看，它由两部分构成：

- **大脑（AI模型）：**负责所有"思考"——推理、规划，并根据当前情况决定下一步执行哪个动作。这是 Agent 的智能来源。
- **身体（能力与工具）：**代表 Agent 被赋予的全部执行能力，决定它"能做什么"。工具范围越广，Agent 能做的事越多。

**类比：**人没有翅膀，就无法执行"飞行"这个动作，但可以行走、奔跑、跳跃、抓取。Agent 也一样——**它的能力边界由配备了哪些工具决定**。

## 三、自主性（Agency）的五个等级

Agent 的自主性不是"有或没有"，而是一个从低到高的连续光谱：

| 等级 | 名称 | AI 输出对程序的影响 | 典型代码模式 |
|-|-|-|-|
| ☆☆☆ | 简单处理器 | 无影响，仅处理后输出 | process_llm_output(llm_response) |
| ★☆☆ | 路由器 | 决定走哪条分支 | if llm_decision(): path_a() else: path_b() |
| ★★☆ | 工具调用器 | 决定调用哪个函数 | run_function(llm_chosen_tool, llm_chosen_args) |
| ★★★ | 多步智能体 | 控制循环与程序继续 | while llm_should_continue(): execute_next_step() |
| ★★★ | 多智能体 | 一套工作流启动另一套 | if llm_trigger(): execute_agent() |

目前真正意义上的 Agent，通常指后两级：能循环执行多步、甚至调度其他 Agent 的系统。

## 四、重要区分：Action ≠ Tool

初学者最容易混淆这两个概念：

- **Tool（工具）：**一个具体的功能单元，如"发邮件""查天气""生成图片"。
- **Action（动作）：**一个要达成的目标动作，**可能需要组合多个工具**才能完成。

**例子：**"给经理发邮件申请推迟会议"是一个 Action，它可能需要先"查日历"确认时间，再"起草邮件"，最后"发送邮件"——使用了多个工具。

## 五、Agent 如何借助工具行动

LLM 本身只能生成文本，那 ChatGPT 为什么能画图？因为开发者额外实现了**工具（Tools）**，模型可以在需要时调用它们。例如，想给 Agent 增加发邮件能力，可以写一个 Python 函数：

```python
def send_message_to(recipient, message):
    """用于向收件人发送邮件"""
    ...

```

当你说"给经理发邮件申请推迟会议"时，模型会生成调用代码：

```python
send_message_to("Manager", "Can we postpone today's meeting?")

```

**工具设计非常关键**：工具设计的好坏，直接决定 Agent 的质量。有些任务需要定制专用工具，有些用通用工具（如 web_search）就够了。

## 六、典型应用场景

- **个人虚拟助手：**Siri、Alexa、Google Assistant 本质都是 Agent——理解提问、检索信息、设置提醒、控制智能设备。
- **客服对话机器人：**回答问题、引导故障排查、创建工单、甚至完成交易，还能从对话中学习改进。
- **游戏 AI 角色（NPC）：**不再死板地按行为树走，而是结合上下文回应玩家，生成更自然的对话，让角色更鲜活。

## 七、新手常见误区

- **误区1：Agent = 聊天机器人。**聊天机器人只"说"不"做"；Agent 能调用工具改变环境、完成任务。
- **误区2：工具越多越好。**工具设计要清晰、可控；工具混乱反而会降低 Agent 的准确率。
- **误区3：忽略"动作≠工具"。**理解二者区别，才能设计出真正可用的 Agent 工作流。

## 八、本节小结

Agent = AI 模型（大脑）＋ 工具能力（身体），核心能力是**理解自然语言、推理规划、与环境交互并观察结果**。它是当前 AI 应用落地的核心形态。
