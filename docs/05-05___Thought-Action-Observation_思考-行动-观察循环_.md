# Thought-Action-Observation（思考-行动-观察循环）

**一句话总述：**Agent 的工作是一个持续循环：思考（Thought）→ 行动（Action）→ 观察（Observation），循环往复直到完成目标。这也是 ReAct 模式的核心。

## 一、三个核心组件

Agent 的工作可以拆成三个不断重复的环节：

- **Thought（思考）：**LLM 部分决定下一步应该做什么。它分析当前情况，规划下一步动作。
- **Action（行动）：**Agent 调用工具，并传入对应的参数。这是真正"动手"的环节。
- **Observation（观察）：**模型反思工具返回的结果，把真实世界的反馈纳入下一次推理。

**编程类比：**整个过程就像一个 **while 循环**——循环一直执行，直到 Agent 的目标达成。

## 二、循环如何被"内置"进 Agent

在很多 Agent 框架中，循环的规则和指南直接写进**系统提示（system prompt）**，确保每一轮循环都遵循既定逻辑。系统提示里通常包含三部分：

1. **Agent 的行为准则**（该怎么表现）
2. **Agent 可用的工具列表**（上一节讲过如何描述工具）
3. **思考-行动-观察循环的指令**（告诉 LLM 按这个模式工作）

## 三、完整例子：Alfred 天气助手

假设我们创建了 Alfred 天气助手，用户问："纽约现在天气怎么样？"

### 第1步：Thought（思考）

Alfred 的内部推理："用户需要纽约的实时天气。我有一个获取天气数据的工具，先调用天气 API 拿到最新信息。"

这一步体现了 Agent 把问题拆解成步骤：先收集必要数据。

### 第2步：Action（行动）

基于推理，Alfred 准备一个 JSON 格式的指令调用天气工具：

```json
{
  "action": "get_weather",
  "action_input": {
    "location": "New York"
  }
}

```

这里明确写清楚了：调用哪个工具（get_weather）、传什么参数（location: New York）。

### 第3步：Observation（观察）

工具执行后，Alfred 收到 API 返回的原始数据：

*"Current weather in New York: partly cloudy, 15°C, 60% humidity."*

这条观察结果被追加进 prompt，作为额外上下文，充当真实世界反馈。

### 第4步：更新思考 + 最终行动

拿到数据后，Alfred 更新推理："现在我有纽约的天气数据了，可以组织答案了。"

然后生成最终回答，把答案发回给用户，循环闭合。

## 四、这个例子告诉我们什么

- **循环迭代直到目标达成：**如果观察结果显示出错或数据不全，Alfred 可以重新进入循环修正方法。
- **工具集成：**调用工具让 Agent 突破静态知识，获取实时数据——这是很多 Agent 的关键能力。
- **动态适应：**每轮循环都把新信息（观察）纳入推理（思考），保证最终答案准确可靠。

## 五、这就是 ReAct 模式

这个例子展示的正是 **ReAct 循环**的核心思想：**Thought（思考）与 Action（行动）交替进行**。ReAct 这个名字来自 Reason（推理）+ Act（行动）。

思考、行动、观察的相互配合，让 Agent 能**迭代式地解决复杂任务**：不仅会推理，还能有效调用外部工具，并根据环境反馈不断修正输出。

## 六、新手常见误区

- **误区1：以为循环只有一轮。**Agent 是持续循环的，观察结果不满意就会再思考、再行动。
- **误区2：混淆"行动"和"观察"。**行动是 Agent 主动调用工具；观察是被动接收工具返回的结果。
- **误区3：忽略系统提示的作用。**循环规则不是模型天生的，而是靠系统提示"灌输"给 LLM 的。

## 七、本节小结

思考-行动-观察循环是 Agent 工作的基本模式：思考决定下一步、行动调用工具、观察吸收反馈，循环直到目标完成。理解了它，就理解了 Agent 如何"边想边做"。
