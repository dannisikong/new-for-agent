# 26 · MCP 架构组件与通信流程

## 一、三大组件职责细化

| 组件 | 职责 | 例子 |
|-|-|-|
| **Host** | ①管理用户交互与权限；②通过 Client 发起对 Server 的连接；③在用户请求、LLM 处理、外部工具之间编排流程；④把结果以连贯形式渲染给用户 | ChatGPT、Claude Desktop、Cursor、Continue、LangChain/smolagents 自建 Agent |
| **Client** | Host 内部组件，与单个 Server 保持 1:1 连接，处理 MCP 协议层细节，做 Host 逻辑与外部 Server 的中介 | 一个 Host 同时连天气 Server + 知识库 Server 时，各对应一个 Client |
| **Server** | 外部程序/服务，把工具、数据源、能力用标准化格式暴露给 Client；可跑在本地（与 Host 同机）也可远程（跨网络）；通常是对现有功能的轻量封装 | 天气服务、知识库、数据库 MCP server |

## 二、7 步通信流程

1. **用户交互**：用户在 Host 里表达意图/提问
2. **Host 处理**：Host 用 LLM 理解请求，判断需要哪些外部能力
3. **Client 连接**：Host 指挥 Client 连到合适的 Server
4. **能力发现**：Client 向 Server 查询它提供哪些 Tool / Resource / Prompt
5. **能力调用**：Host 根据用户需求/LLM 判断，让 Client 调用具体能力
6. **Server 执行**：Server 执行请求的功能，返回结果给 Client
7. **结果整合**：Client 把结果传回 Host，Host 把它并入 LLM 上下文或直接展示给用户

## 三、模块化优势

- 一个 Host 可以通过不同 Client 同时连多个 Server
- 新增 Server 不需要改现有 Host
- 不同 Server 的能力可以自由组合
- 这就是 M×N → M+N 的工程含义

## 四、六大设计原则

| 原则 | 含义 |
|-|-|
| Standardization | 统一协议，AI 连接标准化 |
| Simplicity | 核心协议保持简单，高级能力可选 |
| Safety | 敏感操作必须显式用户批准 |
| Discoverability | 支持运行时动态发现 Server 能力 |
| Extensibility | 通过版本号和能力协商支持演进 |
| Interoperability | 不同实现、不同环境之间可互通 |
