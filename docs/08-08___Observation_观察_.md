# Observation（观察）

**一句话总述：**观察（Observation）是 Agent 感知行动后果的方式——来自环境的各种信号（API 数据、错误消息、系统日志），驱动下一轮思考并指导后续行动。

## 一、什么是 Observation

Observation 是 **Agent 感知自己行动后果的方式**。它提供关键信息，为 Agent 的思考过程提供燃料，并指导未来的行动。

本质上，观察就是 **来自环境的信号**：

- API 返回的数据
- 错误消息
- 系统日志

这些信号引导下一轮思考循环。

## 二、观察阶段 Agent 做三件事

1. **收集反馈（Collects Feedback）：**接收数据或确认信息，判断行动是否成功
2. **追加结果（Appends Results）：**把新信息整合进现有上下文，更新自己的记忆
3. **调整策略（Adapts its Strategy）：**用更新后的上下文，优化后续的思考和行动

**例子：**天气 API 返回 "partly cloudy, 15°C, 60% humidity"，这条观察会被追加到 Agent 的记忆末尾（prompt 结尾）。Agent 据此判断：还需要更多信息，还是可以直接给出最终答案。

**核心价值：**这种迭代式反馈整合，确保 Agent 始终与目标动态对齐，根据真实世界的结果不断学习和调整。

## 三、观察的多种形式

观察的形式非常多——从读取网页文本，到监测机器人手臂的位置。你可以把它们理解为**工具的"日志"**：为行动执行提供文本反馈。

| 观察类型 | 例子 |
|-|-|
| **系统反馈 System Feedback** | 错误消息、成功通知、状态码 |
| **数据变化 Data Changes** | 数据库更新、文件系统修改、状态变化 |
| **环境数据 Environmental Data** | 传感器读数、系统指标、资源使用情况 |
| **响应分析 Response Analysis** | API 响应、查询结果、计算输出 |
| **基于时间的事件 Time-based Events** | 截止时间到达、定时任务完成 |

## 四、结果是如何被追加的？

执行完一个动作后，框架按顺序执行以下步骤：

1. **解析动作：**识别要调用的函数和要使用的参数
2. **执行动作：**真正运行工具
3. **追加观察：**把执行结果作为一条 Observation 追加到上下文中

## 五、回顾：完整的 TAO 循环

至此我们学完了 Agent 的思考-行动-观察循环：

- **Thought（思考）：**决定下一步做什么
- **Action（行动）：**调用工具执行
- **Observation（观察）：**吸收反馈，指导下一轮思考
