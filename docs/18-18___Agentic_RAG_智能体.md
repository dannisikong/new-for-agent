# Agentic RAG 智能体

**一句话总述：**LLM 的通用知识可能过时或无关，**RAG（检索增强生成）**从你的数据中检索相关信息再交给 LLM；而 **Agentic RAG** 更进一步——让智能体**自主决定**用什么工具、走什么流程来回答问题。本单元为 Alfred 构建这样的智能体来筹备舞会。

## 一、为什么需要 RAG？

LLM 在海量数据上训练，获得了丰富的通用知识。但是：

- **世界知识可能不相关**：通用知识 ≠ 你的业务数据
- **信息可能过时**：训练截止之后的新信息，模型不知道

**RAG 的解决方案：**从**你的数据**中查找并检索相关信息，把它**转发给 LLM**，让回答有据可依。

## 二、Alfred 的需求

想想 Alfred 怎么工作：

1. 他被请来帮忙**规划舞会**
2. 他需要查找**最新新闻和天气信息**
3. 他需要**构建并搜索宾客信息**

就像 Alfred 需要翻查你的家庭信息才能帮上忙，任何智能体都需要一种方式来**查找并理解相关数据**。

## 三、Agentic RAG：核心区别

**Agentic RAG 是一种强大的方式：用智能体回答关于你的数据的问题。**

我们可以给 Alfred 传入各种工具来帮他回答问题。关键区别在于：

| 传统 RAG | Agentic RAG |
|-|-|
| 自动在文档之上回答问题 | Alfred **自主决定**使用任何其他工具或流程来回答问题 |
| 固定：检索 → 拼接 → 生成 | 可组合检索、搜索、计算等多种工具 |
| 单一路径 | 按问题灵活选路（检索、网络搜索、查天气……） |

**一句话：**RAG 是"自动帮你查资料"，Agentic RAG 是"把查资料的决策权交给智能体"。

## 四、构建计划（三步走）

1. **第一步：创建 RAG 工具**——检索受邀宾客的最新详细信息
2. **第二步：开发更多工具**——网络搜索、天气更新、Hugging Face Hub 模型下载统计
3. **第三步：整合激活**——把一切集成起来，让 agentic RAG 智能体活起来

## 五、新手常见误区

- **误区1：把 RAG 当成万能。**RAG 解决"知识过时/私有数据"问题，但检索质量取决于知识库组织和检索策略。
- **误区2：Agentic RAG = 多个工具随便堆。**关键是智能体能自主决策"何时用哪个工具"，需要清晰的工具描述。
- **误区3：忘了数据更新。**天气、新闻这类信息必须接实时源，静态知识库解决不了。

## 六、本节小结

RAG 补知识之缺，Agentic RAG 补决策之活。接下来就动手：先建宾客 RAG 工具，再加搜索/天气/统计工具，最后整合成 Alfred 舞会管家。
