# Agentic Frameworks（智能体框架导论）

**一句话总述：**智能体框架（Agentic Framework）是用来构建智能体应用的开发框架；简单任务用纯代码就够，复杂任务（函数调用、多智能体）才需要框架的抽象能力。本单元将学习 smolagents、LlamaIndex、LangGraph 三大框架。

## 一、本单元学什么

欢迎来到第二单元！我们将探索可用于构建强大智能体应用的不同框架：

- **Unit 2.1 · smolagents：**Hugging Face 开发的智能体框架
- **Unit 2.2 · LlamaIndex：**端到端工具，把"上下文增强的 AI 智能体"推向生产
- **Unit 2.3 · LangGraph：**支持有状态（stateful）智能体编排的框架

## 二、什么时候需要框架？

**关键认识：围绕 LLM 构建应用时，智能体框架并不总是必需的。**它们为工作流提供灵活性，能高效解决特定任务，但不是任何时候都需要。

### 简单场景：纯代码就够了

- 预定义工作流（predefined workflows）已经能满足用户请求时，不需要框架
- 例如简单的"提示词链（chain of prompts）"：用普通代码实现即可
- **优势：**开发者对系统有**完全的控制和理解**，没有抽象层的负担

### 复杂场景：抽象开始有价值

当工作流变复杂时——比如让 LLM 调用函数、使用多个智能体——框架的抽象能力就开始发挥作用。

## 三、构建 Agent 需要的核心功能

无论用什么框架，都能识别出这些共同需求：

| 组件 | 作用 |
|-|-|
| **LLM 引擎** | 驱动系统的底层大模型 |
| **工具列表** | 智能体可以访问的工具集合 |
| **解析器（Parser）** | 从 LLM 输出中提取工具调用 |
| **系统提示（System Prompt）** | 与解析器保持同步的指令 |
| **记忆系统** | 保存和读取对话上下文 |
| **错误日志与重试机制** | 控制 LLM 出错，失败后重试 |

接下来我们会看到：这些主题在 smolagents、LlamaIndex、LangGraph 中分别是如何解决的。

## 四、三大框架速览

| 框架 | 定位 |
|-|-|
| **smolagents** | Hugging Face 开发的轻量智能体框架 |
| **LlamaIndex** | 端到端工具，用于把上下文增强的 AI 智能体部署到生产环境 |
| **LangGraph** | 支持有状态编排的智能体框架 |

## 五、新手常见误区

- **误区1：做 LLM 应用就必须用框架。**简单任务用纯代码更可控，别过度设计。
- **误区2：框架越多越好。**先明确需求，再选合适的框架；三个框架各有侧重。
- **误区3：忽略底层组件。**无论用什么框架，"LLM + 工具 + 解析器 + 记忆"这些基础都相通。

## 六、本节小结

智能体框架不是必需品，而是复杂场景下的利器。理解"何时用、为什么用"，再逐个掌握 smolagents、LlamaIndex、LangGraph，就能选出最适合项目的工具。
